# explain-concept — 概念讲解编排

## 讲解结构（默认四层，按需裁剪）

1. **一句话本质 + 类比**：用用户已知的东西打比方。类比要标注边界（"到这里就不像了"）。
2. **机制分解**：组成部分 / 运行流程 / 关键因果链。
3. **对比锚定**：与用户已知概念对比（相同点、本质差异）。
4. **边界与误区**：什么时候不成立、常见误解。

原则：**先直觉后严谨**；一次只讲一个层次，等用户追问再深入，不倾倒全部细节。
语言：中文，术语首次出现给英文原文。

## 可视化选型表

| 特征 | 形式 | 用什么 |
|---|---|---|
| 流程/管道/架构/时序，结构确定 | 精确结构图 | `../viz-d2/SKILL.md` |
| 概念关系、发散讨论、手绘感 | 白板 | `../viz-excalidraw/SKILL.md` |
| 回复里顺带的小图 | 内联 | mermaid 代码块（无需渲染） |
| 长文、需批注、需留存 | 文档 | 用户级 lark-doc 技能（飞书） |
| 图要留存在飞书白板协作 | 飞书白板 | 用户级 lark-whiteboard 技能 |

拿不准时：先文字讲透 → 问一句"要不要来张图？"或直接给一张最合适的。
讲解复杂系统时主动出图；简单概念不要强行配图。

## 产物落盘

| 上下文 | 位置 |
|---|---|
| 活跃任务中 | `tasks/<活跃任务>/artifacts/` |
| 无任务（随手问） | `scratch/`（不进 git） |
| 用户明确要留存 | `knowledge/insights/<主题>.md`（追加，注明日期；present2me 工作区） |

## 升级路径

- 一个概念讲解演变成多轮学习（如精读论文）→ 建议转正式任务：
  走 `../task-context/SKILL.md` 建任务文件夹，或参考插件目录 `workflows/study-paper.md`。
- 讲解产物要变成博客 → `workflows/blog-cowrite.md`（插件目录；仓库内根目录为软链）。

## 质量自检（发给用户前）

- [ ] 第一段不看图也能懂吗？
- [ ] 类比是否贴切且标了边界？
- [ ] 图是否只讲一件事？（一张图讲两件事 → 拆两张）
- [ ] 有没有把"我猜的"当成"事实"讲？（推测要显式标注）
