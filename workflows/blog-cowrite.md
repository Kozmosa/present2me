# Workflow: 博客共写（口述 → 飞书批注 → 修订 → 风格沉淀）

> 场景：用户口述概念/想法，Agent 写初稿到飞书文档，用户手动加 comments，
> Agent 拉取评论修订，定稿后沉淀"改前/改后"版本对，逐步学习用户文风。

## 前置

- task-context 协议（`.agents/skills/task-context/SKILL.md`）。
- lark-cli 已授权（`tools/status.sh` 确认；飞书操作用用户级 lark-doc 技能，`--as user`）。

## 步骤

### 1. 口述捕获

- 建任务 `tasks/$(date +%F)-blog-<slug>`。
- 用户口述要点逐字/近逐字记入 `sources/dictation.md`（含口误与重复，别过早加工）。
- 追问缺失的关键信息：目标读者、发表渠道、想突出的核心观点。**只问这三个，别盘问**。

### 2. 初稿 v1

- **写之前必读** `knowledge/style-profile.md`（已积累的风格档案）。
- 写 `artifacts/draft-v1.md`，遵循档案中已确认的偏好；无档案时按默认风格
  （中文、先直觉后严谨、口语化但不散）。
- 创建飞书文档（lark-doc 技能；文档操作注意 JSON 判定用 `ok == true`），
  正文导入初稿，**URL 回填 TASK.md**。
- 告知用户："初稿已就位，请在飞书里批注，改完喊我。"

### 3. 用户批注（等待态）

- 用户在飞书文档中手动加 comments。
- TASK.md 状态标注 `awaiting-review`，本工作流挂起。

### 4. 拉取评论并修订

- 用户说"review 完了/开始改吧"后，通过 lark-doc 技能拉取文档当前内容与评论。
- 若评论拉取不被支持：请用户把评论复制到 `sources/comments.md` 或口头转述。
- 逐条处理评论：修订正文 → `artifacts/draft-v2.md` → 更新飞书文档。
- 意见不认同时：在任务文件夹 `artifacts/disagreements.md` 记录双方理由，
  面向用户口头提出，**以用户为准**。

### 5. 迭代至定稿

- 重复 3-4。每次修订版本号 +1，**旧版一律保留**。

### 6. 定稿沉淀（本工作流的核心价值）

用户宣布定稿后，在 `knowledge/style-pairs/$(date +%F)-<slug>/` 建立：

```
before.md     # Agent 的最后一个版本（未被用户采纳前的最后稿）
after.md      # 用户定稿版（从飞书拉回）
diff-notes.md # 改动分析（模板见下）
```

`diff-notes.md` 模板：

```md
# 改动分析：<slug>（YYYY-MM-DD）

## 结构
（段落顺序/开头结尾/详略安排上的改动）

## 语气与用词
（删了哪些 AI 味用语、换了哪些词、口语化程度）

## 内容取舍
（用户删了什么、补了什么、哪些推测被替换为事实）

## 可泛化的规律
（本次学到的、下次写初稿就该应用的 1~3 条）
```

然后**合入 `knowledge/style-profile.md`**：

- 把「可泛化的规律」写进「已确认的偏好」区，标注日期与来源任务。
- 与旧条目冲突时：以近期为准，旧条目移入「已过期」区而非删除。
- 档案保持 ≤ 150 行，超出时合并同类项。

### 7. 归档

- 任务移 `archive/`；若博客公开发表，把发布链接记入 TASK.md。

## 铁律

- style-pairs 与 draft-vN 是**风格学习语料**，只增不改不删。
- 未经用户确认，不改飞书文档内容（lark-cli 高危写操作需确认，遵守其约定）。
